# 로그인·약관창 반응형 수정 — 2026-10-20

## 원인과 변경

피드백 이미지의 로그인 방법 선택창은 흰 배경 바깥의 `SafeArea`가 하단 여백을
확보해 홈 인디케이터 부분에 뒤 화면의 회색 오버레이가 드러났다.
안전 영역 이외에도 마지막 버튼 아래에 36pt 여백이 중복으로 있었다.

- 로그인창과 같은 구조인 회원가입 약관창 모두 흰 배경 안쪽에서 안전 영역을 처리한다.
- 로그인창 마지막 버튼 아래 여백은 안전 영역에 16pt만 더한다.
- 화면 높이가 부족하면 창의 내용이 스크롤된다. 위쪽은 상태 표시줄과 노치를 피한다.
- 로그인 버튼은 최소 52pt를 유지하고, 큰 글자에서는 줄바꿈과 함께 높이가 늘어난다.
- 약관 행도 최소 높이만 지정해 좁은 화면과 큰 글자에서 내용에 맞게 늘어난다.

## 자동 검증

수정 전 iPhone 16 크기의 회귀 검사에서 마지막 버튼 아래 여백 36pt로 실패하는 것을
재현했다. 수정 후 아래 크기에서 로그인창과 약관창의 하단 안전 영역 픽셀이 흰색이고,
버튼이 안전 영역 위에 위치하며 불필요한 하단 여백이 없는 것을 확인했다.

| 화면 조건 | 논리 크기 | 위/아래 안전 영역 |
| --- | --- | --- |
| iPhone SE 크기 | 375×667 | 20/0pt |
| 작은 Android 크기 | 320×568 | 24/24pt |
| iPhone 16e 크기 | 390×844 | 47/34pt |
| iPhone 16 크기 | 393×852 | 62/34pt |
| 큰 iPhone 크기 | 440×956 | 62/34pt |

추가로 320×568에서 글자 크기 200%, 393×320에서 130%를 적용해 스크롤로 모든
로그인 방법과 약관 동의 후 다음 버튼을 조작할 수 있고, 각각 콜백이 실행되는지 확인했다.

- `flutter test --no-pub test/auth_sheet_layout_test.dart test/portrait_layout_test.dart`: 17개 통과.
- 변경 파일 분석: 오류·경고 없음. 기존 `withOpacity` 관련 안내 2건.
- iOS debug 시뮬레이터 빌드 및 BASE_URL 설정 검사 통과.

## iPhone 16 시뮬레이터 화면 확인

- iPhone 16 / iOS 18.6 / 393×852pt에서 수정본 앱을 실행했다.
- XCTest로 온보딩의 로그인 버튼을 눌러 두 로그인 방법이 화면에 표시되고 조작 가능한지 확인했다.
- 회원가입 약관창도 열리고, 동의하지 않은 다음 버튼은 비활성화되는 것을 확인했다.
- 다시 로그인창을 여는 전환까지 포함한 XCTest 1개가 통과했다.
- 실제 캡처에서도 두 창 모두 화면 아래쪽 좌/중/우 픽셀이 RGB(255,255,255)로,
  홈 인디케이터 영역까지 흰색 배경이 이어진다.
- 로그인창 마지막 버튼의 아래 좌표는 802pt이고, 화면 높이 852pt에서 안전 영역 34pt와
  안쪽 여백 16pt를 정확히 확보한다.

화면 증거: [로그인 선택창](iphone-16-login.png), [회원가입 약관창](iphone-16-terms.png).

기기별 크기 검사는 위젯 테스트이며 iPhone 16 화면 확인은 시뮬레이터 결과다.
기존 다른 iOS·타이머 작업은 수정하거나 이번 커밋에 포함하지 않았다.
