## 실서버와 새 명세의 차이

[현재 서버 OpenAPI](https://api.whoreads.kro.kr/v3/api-docs)에는 `UpdateStatus`의
`reading_status`, `reading_page`만 있고 `started_at`, `completed_at` 입력 필드가 없다.
상세 응답 `ReadingInfo`에도 새 `user_book_id` 필드가 없다.
[백엔드 PR #233](https://github.com/WhoReads-umc-9th/whoreads-backend/pull/233)은 병합됐지만,
현재 서버의 문서와 실제 날짜 수정 결과에는 해당 변경이 반영되지 않았다.

기기에서 `{ "reading_page": 25 }` 수정 시 서버 내부 오류를 재현했다.
현재 상태를 함께 보내는 `{ "reading_status": "READING", "reading_page": 25 }`로
보완한 뒤 실제 저장 및 재조회 성공을 확인했다. 이 요청은 새 명세에서도 허용된다.

날짜 수정 요청 후에는 상세를 재조회해 요청한 날짜와 비교하고, 서버가 변경을 무시하면
미반영 안내를 표시한다. 시작일·완료일 저장과 재독 시 완료일 초기화의 실서버 검증은
새 API 배포 후 다시 확인해야 한다. 백엔드 코드나 배포 설정은 변경하지 않았다.

## Android API 36 에뮬레이터: 앱 기능 미검증

기존 `Medium_Phone_API_36.0`에서 시작 및 콜드 부팅을 시도했지만 Android 시스템에서
`DeadSystemException`, 패키지 서비스 `Broken pipe (32)`가 발생했다.
별도 임시 AVD에서 새 부팅과 소프트웨어 그래픽 설정으로 재시도했다.
처음에는 APK 설치가 `Error: device is still booting`으로 거부됐다.
이후 `sys.boot_completed=1`까지 확인하고 APK를 다시 전송했지만 설치가 완료되지 않아
앱 기능 검증을 진행하지 못했다. 임시 에뮬레이터는 종료하고 생성한 AVD를 정리했다.
기존 AVD 설정을 초기화하거나 Android SDK를 교체하지 않았다.
에뮬레이터에서 앱 상태·날짜·페이지 수정이 통과했다고 판정하지 않았다.
