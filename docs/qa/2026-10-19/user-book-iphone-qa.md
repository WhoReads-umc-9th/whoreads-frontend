# UserBook iPhone 시뮬레이터 검증 — 2026-10-19

## 환경과 범위

- iPhone 16e / iOS 26.0, 세로 390×844pt (화면 캡처 1170×2532px).
- 현재 작업 코드의 iOS debug 앱을 새로 빌드해 `com.example.whoreads`에 업데이트 설치했다.
- `flutter build ios --simulator --debug --no-pub` 성공.
- `release_config.py write-env`, `verify-server`, 앱 번들 `audit` 통과. 앱 환경 파일에는 BASE_URL만 포함한다.
- 실제 서버 `https://api.whoreads.kro.kr`에 연결했다. 테스트용 모의 API나 가짜 로그인 응답을 사용하지 않았다.
- 최초 기존 세션에서는 회원/서재 조회에 HTTP 500이 발생했다. 앱에서 로그아웃 후 카카오 로그인 버튼을 눌러 기존 카카오 세션으로 복구했고, 회원 정보와 기존 서재가 정상 조회됐다. 비밀번호나 인증 토큰을 추출하거나 기록하지 않았다.
- Mac 잠금으로 호스트 마우스 입력이 전달되지 않아, 임시 XCTest UI 도구로 시뮬레이터 안의 앱 버튼·키보드·달력을 직접 조작했다. 앱 코드를 테스트 전용으로 교체하지 않았다.
- 연결 가능한 실제 iPhone은 없어 실기기 검증은 포함하지 않는다. 이번 범위는 인물 사진과 UserBook 화면이며, APNs·타이머·배포 검증은 포함하지 않는다.

## 실제 서버와 화면 검증

기존 서재 두 권은 수정하지 않고, 서재에 없던 **넷 포지티브**(전체 448페이지)를 검증용으로 사용했다.

| 항목 | 관찰 결과 |
| --- | --- |
| 인물 탭 → 리처드 브랜슨 상세 | 사진 100×133.3pt로 인물 탭과 같은 세로 3:4 비율 확인 |
| 서재에 없는 책에서 읽는 중 선택 | 버튼 한 번으로 서재 추가와 상태 변경, 시작일 2026-10-19 표시 |
| 읽은 페이지 0 입력 후 저장 | `읽은 페이지는 1 이상이어야 합니다.` 표시, 저장 차단 |
| 읽은 페이지 449 입력 후 저장 | `전체 페이지 수를 초과할 수 없습니다.` 표시, 저장 차단 |
| 읽은 페이지 25 저장 | 25/448p, 5% 표시 |
| 다 읽음 바로 선택 | 448/448p, 100% 표시; 페이지 수정 버튼 숨김 |
| 완료일을 시작일보다 이른 2026-10-17로 선택 | `입력할 수 없습니다` 팝업과 날짜 순서 안내 확인 |
| 읽는 중으로 복귀 | 기존 독서량 25/448p 복원, 완료일 숨김 |
| 담아둠 → 읽는 중 | 독서량 25/448p 유지, 담아둠에서는 독서량과 날짜 숨김 |
| 상세를 나갔다 다시 열기 | 실제 서버 재조회 후 읽는 중과 25/448p 유지 |
| 달력에서 미래 날짜 | 2026-10-20 이후 날짜와 다음 달 이동 비활성화 확인 |
| 시작일을 2026-10-17로 변경 | **서버 미반영**. 재조회 시 2026-10-19로 유지되고 `날짜 변경이 서버에 반영되지 않았습니다. 다시 확인해주세요.` 표시 |

상태와 페이지 변경은 실서버에서 확인했다. 날짜 저장과 재독 시 서버 완료일 초기화는 새 API 배포 후 재검증이 필요하다. 서버 명세 차이와 삼성 실기기 결과는 [Android 검증 기록](user-book-device-qa.md)을 참고한다.
